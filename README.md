## 图文与视频发布

在有序图库内整理素材、文案和发布设置，点击带入后立即进入抖音发布页面，由 Chrome 扩展展示完整作品并独立上传素材。上传与草稿准备完成后，同一标签页切换为抖音原生编辑界面，可以继续修改图片、文字和设置；最终发布由用户手动确认。App 插件和 Chrome 扩展的版本均为 **1.0.0**。

## 安装

1. 使用当前有序图库 App，并保持 App 运行。
2. 下载 [App 插件安装包](https://github.com/dteer/lumaindex-extensions/releases/download/douyin-v1.0.0/douyin-1.0.0.luma-plugin.zip)，在有序图库的“设置 → 插件 → 从文件导入”中安装。也可从 GitHub 安装，输入 `https://github.com/dteer/lumaindex-extensions`。
3. 下载 [Chrome 扩展安装包](https://github.com/dteer/lumaindex-extensions/releases/download/douyin-v1.0.0/douyin-chrome-extension.zip) 并解压。Chrome 打开 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，指定包含 `manifest.json` 的目录。
4. 已加载本地扩展时，将目录更新为本次文件后点击扩展的重新加载。确认 App 插件与 Chrome 扩展均显示 1.0.0，并在 Chrome 登录抖音创作者中心。

本地构建目录中的 `抖音发布助手.luma-plugin.zip` 与 `Chrome扩展/` 可按相同步骤安装。

## 编辑与带入

- 在来源或集合中选择素材，通过素材菜单或顶部插件菜单带入“抖音发布助手”。
- 图文模式支持拖动排序、移除素材及还原本次带入素材。单击缩略图切换预览，双击查看大图；预览支持滚轮和方向键切图。
- 在 App 填写标题、描述及话题文本，选择可见范围、保存权限、发布时间和城市地点。正式话题关联、好友、配乐以及需要额外确认的地点，在恢复后的原生页面中处理。
- 点击“带入抖音编辑页”后，发布页面立即显示本次素材顺序、文案、封面、设置和上传进度，无需等待全部上传完成才看到作品，也无需在中转页再次操作。每次带入使用 App 的完整快照；同一账号、同一 App 草稿再次带入时，可复用已成功上传且版本未变化的资源。
- App 右侧的手机式预览仅供参考，不代表真实账号、上传状态或发布结果。
- 视频模式每次准备一个 MP4、MOV 或 WebM；插件不转码、不剪辑，无法播放的编码需先转换。

## AI 文案与图片分析

- 点击顶部“AI 文案”打开弹窗，主页面保留基础信息、发布设置和作品预览。
- 提示词内置默认模板，可修改、保存并恢复默认；作品信息与提示词随当前图库的插件状态保存。
- 首张素材所在目录的末级名称可作为主题线索；生成结果末尾附本机当天的 `#YYYYMMDD`。目录名只用于提示与地点搜索词，真实地点仍需从查询结果中确认。
- 通过图库后端的 AI 连接生成标题和描述，先预览再应用；替换现有文案需确认，生成失败保留原文案，支持取消。
- “结合图片分析”默认关闭。开启后默认选首张可用图片，可在缩略图右下角勾选，最多 6 张；插件只提交素材 ID，后端读取已登记缩略图并转换为最长边 400 像素的 JPEG，再发送至 AI 服务。
- 缩略图不可用时不会回退读取原图。视频当前仅使用文字信息。图片分析会增加用量和耗时，模型需支持图片输入。
- 需要包含 `/api/v1/ai/copy` 能力的新版有序图库 App；本次按要求保持 App 插件与 Chrome 扩展版本为 **1.0.0**，更新后请重新导入插件。

## 上传与草稿恢复

Chrome 扩展按以下顺序执行一次带入：

1. 立即进入带本次任务标记的图文或视频发布路由，由扩展自有 iframe 展示完整素材网格、标题、描述、封面预览、发布设置和进度；上传期间内容只读。
2. 在准备页确认当前账号并读取该账号的原生草稿快照。图文采用两条单素材流水线，每条按“读取并校验一张 → 上传 → 保存成功资源记录 → 释放文件引用”处理，再读取下一张；视频按单文件执行 VOD 上传。图片与视频都校验上传结果；视频还需等待抖音转码完成。
3. 每项资源成功后保存按账号、素材 ID 和文件版本隔离的检查点。上传密钥只保留在本次任务内存中，不进入检查点、页面或日志。
4. 全部素材就绪后，以 App 当前内容生成完整 JSON 草稿，包含图片顺序或视频资源、标题、描述、封面、地点和发布设置。
5. 在准备页再次确认账号与原草稿未变化，先保留最近一份被替换草稿的备份，再执行比较后写入（CAS）并回读验证。
6. 同一标签页进入不带准备标记的原生草稿恢复路由；仅视频的“不允许保存”按下述例外自动恢复，其余内容只读检查实际展示。确认恢复后，用户可继续通过原生控件编辑并手动发布。

正文图片同时最多处理两项完整素材任务，不先把整批原文件留在内存中。已完成素材只保留账号、素材身份、文件版本和服务端资源元数据；最终草稿按 App 顺序组装。读取或上传失败后停止领取新素材，已经在途的任务结算并保存成功记录，再结束本次带入。

准备页中的缩略图只请求图库的 400 像素预览，最多四项并发，不为展示重复读取原图。单张缩略图失败时保留文件名占位；上传失败时完整作品内容与错误提示保留在页面中，不清空预览和文案。

扩展不调用抖音 React、Slate、上传 SDK 或私有组件回调，不模拟上传控件和文本输入，也不改写控件原型。准备期间的全部界面由扩展渲染。唯一的原生控件操作例外是视频“不允许保存”：用户已授权在原生缓存恢复后通过 checkbox 的标准 `click()` 恢复该选项，范围与停止条件见下文。

同一 App 草稿再次带入时，只有账号、路由和页面标记仍匹配才复用其编辑标签页；先离开旧编辑器，再写入新草稿。用户已导航离开的页面不会被接管。

同一账号同时只处理一份带入任务。写入期间发现账号切换、其他标签页修改草稿或当前缓存属于已发表/已定时提交作品的编辑稿时，停止写入并提示。相同任务 ID 在写入开始后不得重复提交，避免重复交接；需要再次带入时从 App 发起新任务。

## 资源复用与完整快照

- 同一账号下，仅复用素材 ID、文件版本及上传结果均匹配的资源；不凭文件名或文件大小认领已有图片。
- 新增或修改的素材由扩展上传，移除和排序只改变新草稿，不操作原生图片卡片或重新上传未变素材。
- 成功资源逐项保存。后续上传、封面处理、草稿写入或展示核对失败时，再次带入可复用已保存结果。尚未得到成功结果的请求不当作已完成。
- **每次 App 带入都是完整替换快照。** 在抖音原生页进行的人工修改不会反向写入 App，下一次带入也不会自动合并这些修改。需要保留的文案、顺序与设置，应先在 App 中更新。
- 原生展示核对失败时只重试只读检查，不重复上传或写入。提示“素材已上传”不代表草稿已恢复，更不代表作品已发布。
- 图片上传按申请地址、二进制发送和结果确认区分错误阶段。申请与确认请求各最多等待 60 秒，二进制发送最多等待 300 秒；超时或网络失败保留明确阶段提示和已成功的资源记录，不自动重复上传。

## 封面与发布设置

图文模式可选择封面素材并在 App 确认裁剪。扩展读取图库预览完成裁剪，独立上传封面后写入新草稿，正文图片及其顺序不受封面上传影响。相同素材版本与相同裁剪参数可复用已上传封面。

支持公开、好友可见或仅自己可见，允许或不允许保存，立即发布或定时发布。定时时间按本机时区输入，需在 2 小时后至 14 天内。这些设置随草稿一次性带入，恢复后由用户继续核对和修改。普通视频页初始化可能将“禁止保存”改回“允许”，因此仅此选项使用已授权的原生控件例外自动恢复。图文和视频“允许保存”不进入此操作。扩展不调用发布接口、不点击发布按钮。

视频“不允许保存”的自动恢复先等待其他内容在原生页面完整就绪，再绑定本次任务标记与完整页面 URL，只操作唯一可见且同组的“允许=1 / 不允许=0”原生 checkbox。校正最多点击 3 次，总时限为 30 秒；“不允许”的 `checked` 与标签 `data-checked` 必须一致为选中、“允许”一致为未选中，并连续稳定 2.5 秒后才确认成功。监听该组的可信 `pointerdown`、`keydown` 与 `click`，用户一旦操作便立即停止自动校正，保留用户选择；页面导航、标记变化或控件无法唯一确认时也停止。任务结束清理监听，不在后台持续改写该选项。

## 暂存与关闭

- 每个图库独立保存插件状态，图文和视频各有一份草稿；记录素材 ID、顺序、文案及设置，不复制媒体文件。
- 编辑时保留恢复副本；“暂存”在本机保存成功后确认。保存失败会提示，并保留当前页面。
- 页面或宿主插件栏关闭、重新加载时，未暂存修改提供“暂存并关闭 / 不保留并关闭 / 取消”。“不保留”删除当前图库的图文和视频草稿；“删除草稿”只删除当前模式。
- 新素材遇到旧草稿时可选择覆盖或继续。继续会保留旧文案和顺序，按素材 ID 去重追加；覆盖只替换对应模式。
- 侧栏切换或退出 App 后可恢复已保存状态；强制退出时尚未完成的写入不保证保留。禁用或卸载插件不会主动清除草稿。
- 草稿是本机状态，不是抖音云端草稿。图库路径变化会视为另一份状态；来源离线或原文件移除可能导致无法预览、上传。

## 限制与验证范围

- 图文支持 1–35 张，单张不超过 50 MiB，不设整批图片合计大小上限；视频单个不超过 80 MiB。图片通过两条单素材流水线控制在途文件数量，实际上传仍需满足平台规则。
- JPEG、PNG、WebP 使用原文件；RAW、HEIC 等其他图片格式使用图库已生成的 2048 浏览图。实况照片使用静态图片素材。浏览图缺失时提示失败。
- App 和 Chrome 需保持运行。若 App 本机端口改变，从 App 再次带入即可，已有本机草稿保留。
- 原生草稿协议或可见结构无法确认时，停止相应操作并提示。协议与页面可能随平台更新变化，检查失败不能按成功处理。
- 独立上传、原生恢复及视频保存权限例外已有实机记录；发布准备页已通过完整展示、缓存隔离和图片上传至原生恢复的验收。本轮取消图文总量限制及单素材流水线的最终回归与实机状态另行确认，详细边界见 [验证记录](VALIDATION.md)。

## 城市与地点
扩展信息中的标签位置先选择城市，再搜索真实地点。Chrome 扩展开启“启用 App 连接”后，未连接时由地点或合集查询显示手动连接入口；点击“连接 Chrome（手动打开）”完成配对，再重试查询。查询本身不会打开浏览器或抢占焦点。查询与地点带入均由本仓库 browser/ 中的扩展处理。扩展直接查询真实地点，并在提交草稿前重新确认候选；需要额外人工确认的地点，提示在原生页面完成选择。无需 AppleScript、Chrome Apple 事件设置或主 App 的浏览器自动化权限。
主 App 仅提供按插件隔离、进程内临时的通用 WebSocket 通道，不保存消息，不理解抖音协议。Chrome 扩展后台持有连接、每 20 秒保活，并在短暂断开或后台重启后恢复仍存在的 App 通道。连接页不管理连接；关闭 App 插件页会结束通道。需要 Chrome 116 或更新版本。
扩展不读取或保存 Cookie；对抖音的同源查询由浏览器携带当前登录会话，不改变设备定位。带入后仍需用户核对并手动发布；协议或页面结构无法确认时停止并提示。
城市数据来自 [Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China) 的 cities.json（2026-11-15 获取），仅用于城市代码匹配。

## 作品合集

在 App 的“扩展信息 → 加入合集”读取当前抖音账号的已有普通免费合集，支持选择、清除和按页加载。图文、视频的选择分别随本机草稿保存；加入合集的作品必须公开可见，修改为好友或私密后需清除合集或恢复公开再带入。

查询和带入均由 Chrome 扩展独立完成。列表每页十条，沿用平台游标；带入前和素材上传完成后分别重查账号、合集名称及当前集数，合集失效时保留已上传素材供重试。准备页展示所选合集，随后恢复到原生合集和集数控件，交接完成后仍可人工修改。合集创建、付费合集、会员内容和短剧的专用配置不在此选择器中提供。

### Chrome 扩展配置

点击工具栏的「有序图库抖音联动」图标，或在扩展详情中打开「扩展程序选项」，可查看 App 后台连接状态、刷新状态或主动断开连接。配置页同时说明城市与地点查询的使用方式。关闭配置页不会断开连接；Chrome 扩展提供“启用 App 连接”开关；App 查询时若未连接，会显示手动配对入口，连接完成后可重试。交接标签页自动关闭。

## 协议与模块边界

`staging-content.js` 在带本次任务标记的发布路由挂载扩展 iframe，`staging.html/css/js` 渲染完整只读作品、缩略图与进度；`staging-rules.json` 声明仅该准备主文档适用的脚本隔离规则。`image-upload.js` 与 `video-upload.js` 负责扩展自有上传协议；`media.js` 的 `prepareFile` 只读取一个素材，图文保留单张 50 MiB 限制、视频保留单个 80 MiB 限制；`import-images.js` 负责两条完整单素材流水线、资源复用和检查点，`import-video.js` 负责单视频的上传与转码编排；`draft-model.js` 生成纯 JSON 草稿；`draft-page.js` 负责隔离世界中的固定请求、草稿存储、只读展示核对及上述视频保存权限例外；`worker.js` 统一校验来源、账号、并发任务与交接回执。

准备路由为 `https://creator.douyin.com/creator-micro/content/post/{image|video}?luma_import=<小写 UUID v4>`。Chrome [声明式网络规则](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)仅对精确匹配的主文档追加 `Content-Security-Policy: script-src 'none'`，阻止原生脚本在准备期间初始化及写缓存；扩展 iframe 使用独立文档。内容脚本只接管同样的规范 URL，并校验任务标记；其他页面以及最终不带 `luma_import` 的原生恢复页均不受该规则限制。

协议依据为 2026-11-16 核对的抖音创作者页面静态契约。ImageX 的申请与确认流程可参考官方 [获取文件上传地址](https://docs.volcengine.com/docs/veimagex/get-file-upload-address?lang=zh) 和 [确认上传结果](https://docs.volcengine.com/docs/veimagex/confirm-upload-and-report-upload-result?lang=en)；抖音使用的主机、资源状态及草稿字段以已核对契约为准，不将通用文档视为抖音接入承诺。二进制上传地址仅允许已核对的 `*.bytedancevod.com` 子域与`snssdk.com`、`douyin.com` 下单层 `tos-` 前缀存储主机，运行时拒绝其他主机和重定向。运行包不包含抓包数据、平台源码、用户素材或上传凭据。
